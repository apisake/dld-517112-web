12.1 ภาษาอธิบายฮาร์ดแวร์คืออะไร

ในบทที่ 11 เราได้เห็นว่าการโปรแกรมอุปกรณ์ PLD หรือ FPGA เริ่มต้นจากขั้นตอนการออกแบบวงจร (design entry) ซึ่งนิยมทำด้วยภาษาอธิบายฮาร์ดแวร์ (Hardware Description Language: HDL) บทนี้จะแนะนำภาษาดังกล่าวในระดับเบื้องต้น โดยใช้ภาษา Verilog ตามมาตรฐาน IEEE 1364-2005 เป็นหลัก และนำวงจรที่ได้ศึกษามาแล้วตั้งแต่บทที่ 7 ถึงบทที่ 10 เช่น วงจรบวก มัลติเพล็กเซอร์ ตัวถอดรหัส วงจรนับ และ state machine มาเขียนเป็นโค้ด ทดสอบด้วยการจำลองการทำงาน แล้วดูว่าเครื่องมือสังเคราะห์วงจรแปลงโค้ดเหล่านั้นกลับเป็นเกตและฟลิปฟลอปได้อย่างไร

HDL มีหน้าตาคล้ายภาษาโปรแกรมทั่วไป แต่มีความหมายต่างกันโดยสิ้นเชิง ภาษาโปรแกรมอย่างภาษา C อธิบายลำดับของคำสั่งที่ซีพียูทำทีละคำสั่ง ส่วน HDL อธิบายโครงสร้างและพฤติกรรมของวงจร ซึ่งทุกส่วนทำงานพร้อมกัน (concurrent) ตลอดเวลา เช่นเดียวกับเกตทุกตัวบนแผงวงจรที่ทำงานไปพร้อม ๆ กัน ผู้เรียนจึงควรคิดถึง “วงจร” ที่ต้องการก่อนเสมอ แล้วจึงเขียนโค้ดเพื่ออธิบายวงจรนั้น

12.1.1 HDL กับการวาดผังวงจร

ในบทก่อน ๆ เราออกแบบวงจรด้วยการวาดผังวงจร (schematic) ซึ่งเหมาะกับวงจรขนาดเล็ก แต่เมื่อวงจรมีขนาดหลายพันถึงหลายล้านเกต การวาดผังจะยุ่งยาก แก้ไขยาก และตรวจสอบได้ยาก HDL จึงเข้ามาแทนที่ด้วยข้อดีดังนี้

  • อธิบายได้กระชับ เช่น วงจรบวกขนาด 32 บิตเขียนได้ในบรรทัดเดียว assign s = a + b; แทนการวาด full-adder 32 ตัว
  • ไม่ผูกกับอุปกรณ์ โค้ดชุดเดียวกันนำไปสังเคราะห์ลง FPGA ต่างรุ่นต่างผู้ผลิต หรือทำเป็นชิป ASIC ได้
  • จำลองการทำงานได้ก่อนสร้างจริง เขียน testbench ทดสอบได้ครบทุกกรณีโดยอัตโนมัติ ซึ่งทำไม่ได้กับวงจรบนแผงทดลอง
  • จัดการด้วยเครื่องมือซอฟต์แวร์ได้ เช่น เก็บประวัติการแก้ไข เปรียบเทียบความต่าง และนำโมดูลกลับมาใช้ซ้ำ

12.1.2 Verilog และ VHDL

HDL ที่ใช้แพร่หลายในอุตสาหกรรมมีสองภาษา คือ VHDL (VHSIC Hardware Description Language, มาตรฐาน IEEE 1076) ซึ่งมีรากฐานจากภาษา Ada มีรูปแบบเคร่งครัดและต้องประกาศชนิดข้อมูลชัดเจน และ Verilog (IEEE 1364) ซึ่งมีไวยากรณ์ใกล้เคียงภาษา C กระชับกว่า และปัจจุบันได้พัฒนาต่อเป็น SystemVerilog (IEEE 1800) ทั้งสองภาษาอธิบายวงจรได้เทียบเท่ากัน และเครื่องมือของผู้ผลิต FPGA ทุกรายรองรับทั้งสองภาษา ตัวอย่างด้านล่างเป็นวงจร half-adder (หัวข้อ 7.1.1) ที่เขียนด้วยทั้งสองภาษา

Verilog
module half_adder (
  input  a, b,
  output s, c
);
  assign s = a ^ b;
  assign c = a & b;
endmodule
VHDL
library ieee;
use ieee.std_logic_1164.all;
entity half_adder is
  port (a, b : in  std_logic;
        s, c : out std_logic);
end half_adder;
architecture dataflow of half_adder is
begin
  s <= a xor b;
  c <= a and b;
end dataflow;

จะเห็นว่า VHDL แยกการประกาศส่วนติดต่อ (entity) ออกจากการอธิบายการทำงาน (architecture) ขณะที่ Verilog รวมไว้ในโมดูลเดียว หลักการที่เรียนในบทนี้นำไปใช้กับ VHDL ได้ทันทีเมื่อเรียนไวยากรณ์เพิ่มเติม

12.1.3 การจำลองการทำงานกับการสังเคราะห์วงจร

โค้ด HDL ชุดเดียวกันถูกนำไปใช้กับเครื่องมือสองประเภทดังรูปที่ 12.1 (เทียบกับโฟลว์การออกแบบในรูปที่ 11.8)

  1. ตัวจำลองการทำงาน (simulator) เช่น Icarus Verilog, ModelSim หรือ Vivado Simulator อ่านโค้ดของวงจรร่วมกับ testbench ซึ่งเป็นโค้ดสำหรับป้อนสัญญาณทดสอบ แล้วคำนวณค่าของสัญญาณทุกเส้นตามเวลา เพื่อแสดงเป็นข้อความหรือผังเวลา ขั้นตอนนี้คือ functional simulation ในหัวข้อ 11.3.2
  2. ตัวสังเคราะห์วงจร (synthesizer) เช่น Yosys, Vivado หรือ Quartus แปลโค้ดเป็น netlist คือรายการเกต ฟลิปฟลอป หรือ LUT และการเชื่อมต่อระหว่างกัน ซึ่งเป็นขั้นตอน synthesis ในหัวข้อ 11.3.3 แล้วจึงนำไปจัดวางบนชิปต่อไป

ภาษา Verilog ถูกออกแบบมาเพื่อการจำลองการทำงานก่อน จึงมีคำสั่งหลายอย่างที่จำลองได้แต่ไม่มีวงจรจริงรองรับ เช่น การหน่วงเวลา #10 หรือการพิมพ์ข้อความ $display ส่วนของภาษาที่เครื่องมือสังเคราะห์แปลงเป็นวงจรได้เรียกว่า synthesizable subset โค้ดที่จะนำไปสร้างเป็นวงจรจริงต้องเขียนด้วยส่วนนี้เท่านั้น ส่วน testbench ใช้ภาษาได้เต็มที่เพราะไม่ต้องสังเคราะห์ (รายละเอียดในหัวข้อ 12.6.4)

12.1.4 แนวคิดระดับ RTL

วงจรดิจิทัลแบบ synchronous ทุกวงจรมองได้ว่าประกอบด้วยสองส่วน ตามโมเดลทั่วไปของวงจรซีเควนเชียลในหัวข้อ 9.4.1 คือ รีจิสเตอร์ (กลุ่มฟลิปฟลอปที่เปลี่ยนค่าพร้อมกันที่ขอบสัญญาณนาฬิกา) และวงจรคอมไบเนชันที่คำนวณค่าถัดไปของรีจิสเตอร์จากค่าปัจจุบันและอินพุต การอธิบายวงจรในมุมมองนี้ เช่น “ที่ขอบขาขึ้นของสัญญาณนาฬิกา ให้ q รับค่า q + 1” เรียกว่าการอธิบายระดับ RTL (Register Transfer Level) ซึ่งเป็นระดับที่เครื่องมือสังเคราะห์รองรับดีที่สุดและเป็นระดับที่ใช้ตลอดบทนี้ ผู้ออกแบบกำหนดว่ามีรีจิสเตอร์ใดบ้างและข้อมูลไหลระหว่างรีจิสเตอร์อย่างไร ส่วนรายละเอียดของเกตแต่ละตัวปล่อยให้เครื่องมือสังเคราะห์จัดการ

12.2 โครงสร้างของโมดูล Verilog

12.2.1 โมดูลและพอร์ต

หน่วยพื้นฐานของ Verilog คือโมดูล (module) ซึ่งเทียบได้กับไอซีหนึ่งตัวหรือกล่องหนึ่งกล่องในผังวงจร โมดูลมีชื่อ มีพอร์ต (port) สำหรับติดต่อกับภายนอก และมีรายละเอียดภายในที่อธิบายการทำงาน โครงร่างของโมดูลเขียนได้ดังนี้

module ชื่อโมดูล (
  input  ชื่ออินพุต, ...,      // พอร์ตอินพุต
  output ชื่อเอาต์พุต, ...     // พอร์ตเอาต์พุต
);
  // ประกาศสัญญาณภายใน (wire / reg)
  // อธิบายการทำงานของวงจร (assign / always / โมดูลย่อย)
endmodule

ทิศทางของพอร์ตมีสามแบบ คือ input, output และ inout (สองทิศทาง ใช้กับขาไอซีแบบ tri-state) ชื่อในภาษา Verilog แยกตัวพิมพ์ใหญ่กับตัวพิมพ์เล็ก (a กับ A เป็นคนละสัญญาณ) ประกอบด้วยตัวอักษร ตัวเลข และ _ โดยห้ามขึ้นต้นด้วยตัวเลข ข้อความหลัง // จนจบบรรทัด หรือระหว่าง /* */ เป็นหมายเหตุ (comment) และทุกคำสั่งจบด้วยเครื่องหมาย ;

12.2.2 สัญญาณ wire, reg และเวกเตอร์

สัญญาณใน Verilog มีสองชนิดหลัก ได้แก่ wire ซึ่งแทนสายสัญญาณที่ถูกขับด้วยเอาต์พุตของเกตหรือคำสั่ง assign อยู่ตลอดเวลา และ reg ซึ่งเป็นตัวแปรที่ได้รับค่าภายในบล็อก always หรือ initial ข้อควรระวังคือ reg ไม่ได้แปลว่าเป็นรีจิสเตอร์เสมอไป ถ้าใช้ใน always @* ที่อธิบายวงจรคอมไบเนชัน ก็จะได้เกตธรรมดา จะได้ฟลิปฟลอปก็ต่อเมื่อใช้ใน always @(posedge clk) เท่านั้น

สัญญาณแต่ละบิตมีค่าได้ 4 ค่า คือ 0, 1, x (ไม่ทราบค่า เช่น ฟลิปฟลอปที่ยังไม่ถูก reset หรือมีสองแหล่งขับค่าขัดกัน) และ z (high impedance คือไม่มีแหล่งขับ) สัญญาณหลายบิตเรียกว่าเวกเตอร์ (vector) ประกาศด้วยช่วง [msb:lsb] ดังตัวอย่าง

wire [3:0] a;        // เวกเตอร์ 4 บิต: a[3] เป็น MSB, a[0] เป็น LSB
reg  [7:0] count;    // เวกเตอร์ 8 บิต
wire       x;        // 1 บิต
wire [1:0] y;
assign x = a[2];     // เลือกบิตเดียว (bit-select)
assign y = a[3:2];   // เลือกช่วงบิต (part-select)

12.2.3 การเขียนค่าคงที่

12.3 การอธิบายวงจรคอมไบเนชัน

Verilog อธิบายวงจรได้สามรูปแบบ (modeling style) ซึ่งใช้ปนกันได้ในโมดูลเดียว คือ แบบโครงสร้าง (structural) ที่บอกว่าใช้เกตอะไรต่อกันอย่างไรเหมือนการวาดผังวงจร แบบ dataflow ที่เขียนนิพจน์บูลีนด้วยคำสั่ง assign และแบบพฤติกรรม (behavioral) ที่อธิบายการทำงานด้วยคำสั่ง if และ case ภายในบล็อก always หัวข้อนี้จะเขียนวงจรจากบทที่ 7 ด้วยทั้งสามแบบ

12.3.1 แบบโครงสร้าง: gate primitive

Verilog มีเกตพื้นฐานในตัว (gate primitive) ได้แก่ and, or, not, nand, nor, xor, xnor และ buf การใช้งานเขียนเป็น ชนิดเกต ชื่อ (เอาต์พุต, อินพุต1, อินพุต2, ...); โดยพอร์ตแรกเป็นเอาต์พุตเสมอ และจำนวนอินพุตมีได้หลายตัว โปรแกรมที่ 12.1 คือ half-adder ตามรูปที่ 7.2

โปรแกรมที่ 12.1 half-adder แบบโครงสร้าง (half_adder.v)
1// half adder แบบโครงสร้าง (structural) ด้วย gate primitive
2module half_adder (
3  input  a, b,
4  output s, c
5);
6  xor g1 (s, a, b);   // s = a XOR b
7  and g2 (c, a, b);   // c = a AND b
8endmodule

สำหรับ full-adder ตามรูปที่ 7.5 ต้องมีสายสัญญาณภายในที่เชื่อมระหว่างเกต จึงประกาศเป็น wire ตามชื่อในรูปที่ 12.2 ดังโปรแกรมที่ 12.2

โปรแกรมที่ 12.2 full-adder แบบโครงสร้าง (fa_struct.v)
1// full adder แบบโครงสร้าง (เทียบรูปที่ 7.5)
2module fa_struct (
3  input  a, b, cin,
4  output s, cout
5);
6  wire p, g, t;          // สายสัญญาณภายใน
7  xor u1 (p, a, b);
8  xor u2 (s, p, cin);
9  and u3 (g, a, b);
10  and u4 (t, p, cin);
11  or  u5 (cout, g, t);
12endmodule

การเขียนแบบโครงสร้างให้ผลตรงกับผังวงจรทุกประการ แต่ยาวและไม่สะดวกเมื่อวงจรใหญ่ขึ้น จึงนิยมใช้เฉพาะเมื่อต้องการกำหนดโครงสร้างที่แน่นอน หรือเมื่อนำโมดูลย่อยมาต่อกันเป็นลำดับชั้น (หัวข้อ 12.3.4)

12.3.2 แบบ dataflow: คำสั่ง assign

คำสั่ง assign เรียกว่า continuous assignment หมายความว่าสัญญาณด้านซ้ายจะเท่ากับนิพจน์ด้านขวาตลอดเวลา เมื่ออินพุตตัวใดเปลี่ยน เอาต์พุตก็เปลี่ยนตามทันที ซึ่งตรงกับพฤติกรรมของวงจรคอมไบเนชัน สัญญาณที่ถูกกำหนดด้วย assign ต้องเป็นชนิด wire (พอร์ต output ที่ไม่ได้ระบุชนิดจะเป็น wire โดยอัตโนมัติ) และลำดับของคำสั่ง assign หลายบรรทัดไม่มีผลต่อความหมาย เพราะทุกบรรทัดทำงานพร้อมกัน

โปรแกรมที่ 12.3 full-adder แบบ dataflow (นิพจน์เดียวกับในหัวข้อ 7.1.2) (fa_dataflow.v)
1// full adder แบบ dataflow ด้วย assign
2module fa_dataflow (
3  input  a, b, cin,
4  output s, cout
5);
6  assign s    = a ^ b ^ cin;
7  assign cout = (a & b) | (cin & (a ^ b));
8endmodule

ตัวดำเนินการเงื่อนไข ?: ใช้อธิบายมัลติเพล็กเซอร์ได้โดยตรง โปรแกรมที่ 12.4 เป็น MUX 2-to-1 ที่เลือกข้อมูลขนาด 4 บิต ซึ่งเครื่องมือสังเคราะห์จะสร้าง MUX 2-to-1 จำนวน 4 ชุดที่ใช้สัญญาณเลือก s ร่วมกัน

โปรแกรมที่ 12.4 มัลติเพล็กเซอร์ 2-to-1 ขนาด 4 บิต (mux2.v)
1// 2-to-1 MUX ขนาด 4 บิต ด้วยตัวดำเนินการเงื่อนไข ?:
2module mux2 (
3  input  [3:0] d0, d1,
4  input        s,
5  output [3:0] y
6);
7  assign y = s ? d1 : d0;
8endmodule

12.3.3 แบบพฤติกรรม: always @*

บล็อก always @* (หรือเขียนเต็มว่า always @(*)) หมายถึง “ทำคำสั่งในบล็อกใหม่ทุกครั้งที่สัญญาณใด ๆ ที่ถูกอ่านในบล็อกเปลี่ยนค่า” ภายในบล็อกใช้คำสั่ง if/else, case และการกำหนดค่าด้วยเครื่องหมาย = (blocking assignment) ได้เหมือนการเขียนโปรแกรม สัญญาณที่ได้รับค่าในบล็อก always ต้องประกาศเป็น reg แม้ว่าวงจรที่ได้จะเป็นวงจรคอมไบเนชันก็ตาม

โปรแกรมที่ 12.5 full-adder แบบพฤติกรรม (fa_behav.v)
1// full adder แบบพฤติกรรม (behavioral)
2module fa_behav (
3  input      a, b, cin,
4  output reg s, cout
5);
6  always @* begin
7    {cout, s} = a + b + cin;   // บวก 3 บิต ได้ผล 2 บิต
8  end
9endmodule

โปรแกรมที่ 12.5 ไม่ได้บอกว่าต้องใช้เกตใดเลย เพียงบอกว่า “ผลบวกของ a + b + cin ขนาด 2 บิต คือ {cout, s}” แต่ในหัวข้อ 12.6 เราจะเห็นว่าเครื่องมือสังเคราะห์ได้วงจรเดียวกับรูปที่ 12.2 ทุกประการ สำหรับวงจรที่มีหลายกรณี คำสั่ง case ทำให้โค้ดอ่านง่ายเหมือนตารางค่าความจริง เช่น MUX 4-to-1 ตามตารางที่ 7.8 ในโปรแกรมที่ 12.6

โปรแกรมที่ 12.6 มัลติเพล็กเซอร์ 4-to-1 ด้วยคำสั่ง case (mux4.v)
1// 4-to-1 MUX (1-of-4 data selector, เทียบตารางที่ 7.8)
2module mux4 (
3  input      [3:0] d,      // d[0]..d[3]
4  input      [1:0] s,      // s[1]=S1, s[0]=S0
5  output reg       y
6);
7  always @* begin
8    case (s)
9      2'b00:   y = d[0];
10      2'b01:   y = d[1];
11      2'b10:   y = d[2];
12      default: y = d[3];   // 2'b11
13    endcase
14  end
15endmodule

วงจรถอดรหัส (decoder) 2-to-4 ในโปรแกรมที่ 12.7 ใช้อีกเทคนิคหนึ่ง คือกำหนดค่าตั้งต้น (default) ให้เอาต์พุตทุกบิตเป็น 0 ไว้ที่บรรทัดแรกของบล็อก แล้วจึงกำหนดเฉพาะบิตที่ต้องเป็น 1 ภายหลัง เนื่องจากใน always บล็อกเดียวกัน ค่าที่กำหนดครั้งหลังสุดเป็นค่าที่มีผล

โปรแกรมที่ 12.7 ตัวถอดรหัส 2-to-4 ที่มีขา enable (dec2to4.v)
1// 2-to-4 decoder เอาต์พุต active-HIGH พร้อมขา enable
2module dec2to4 (
3  input      [1:0] a,
4  input            en,
5  output reg [3:0] y
6);
7  always @* begin
8    y = 4'b0000;            // ค่าตั้งต้น: ป้องกันการเกิด latch
9    if (en)
10      y[a] = 1'b1;          // เลือกบิตตามค่า a
11  end
12endmodule
ตัวอย่างที่ 12.2

จงเขียนโมดูล BCD-to-7-segment decoder ตามตารางที่ 7.6 โดยให้เอาต์พุตเป็น active-HIGH เรียงเป็น {a, b, c, d, e, f, g} และให้ทุก segment ดับเมื่ออินพุตเป็นรหัสที่ไม่ใช่ BCD (10–15)

แสดงวิธีทำ

ใช้คำสั่ง case หนึ่งกรณีต่อหนึ่งแถวของตารางที่ 7.6 และใช้ default ครอบคลุมรหัส 10–15 ทั้งหมด

โปรแกรมที่ 12.8 BCD-to-7-segment decoder (bcd7seg.v)
1// BCD-to-7-segment decoder (เทียบตารางที่ 7.6) เอาต์พุต active-HIGH
2module bcd7seg (
3  input      [3:0] bcd,       // D C B A
4  output reg [6:0] seg        // seg = {a,b,c,d,e,f,g}
5);
6  always @* begin
7    case (bcd)
8      4'd0:    seg = 7'b1111110;
9      4'd1:    seg = 7'b0110000;
10      4'd2:    seg = 7'b1101101;
11      4'd3:    seg = 7'b1111001;
12      4'd4:    seg = 7'b0110011;
13      4'd5:    seg = 7'b1011011;
14      4'd6:    seg = 7'b1011111;
15      4'd7:    seg = 7'b1110000;
16      4'd8:    seg = 7'b1111111;
17      4'd9:    seg = 7'b1111011;
18      default: seg = 7'b0000000;  // 10–15: ดับทุก segment
19    endcase
20  end
21endmodule

ในตารางที่ 7.6 รหัส 10–15 เป็น don't care (X) ซึ่งช่วยให้ลดรูปได้มากขึ้นเมื่อออกแบบด้วยแผนผังคาร์โนห์ แต่ในโจทย์นี้กำหนดให้ดับทุก segment จึงใช้ค่า 7'b0000000 แทน ถ้าต้องการให้เครื่องมือเลือกค่าเองก็เขียน default: seg = 7'bx; ได้ โมดูลนี้ผ่านการทดสอบครบทั้ง 16 รหัสอินพุต

12.3.4 การต่อโมดูลเป็นลำดับชั้น

เมื่อเขียนโมดูลแล้ว เราสามารถนำโมดูลนั้นไปใช้ซ้ำในโมดูลอื่นได้ เรียกว่าการสร้าง instance เช่นเดียวกับการนำไอซีหลายตัวมาวางบนแผงวงจร โปรแกรมที่ 12.9 สร้าง parallel adder ขนาด 4 บิตตามรูปที่ 7.8 จาก fa_struct จำนวน 4 ตัว ดังรูปที่ 12.3 การเชื่อมพอร์ตแบบ .ชื่อพอร์ต(สัญญาณ) เรียกว่า named port connection ซึ่งปลอดภัยกว่าการเชื่อมตามลำดับพอร์ต เพราะไม่ต้องจำลำดับของพอร์ต

โปรแกรมที่ 12.9 parallel adder ขนาด 4 บิต แบบลำดับชั้น (adder4.v)
1// parallel adder ขนาด 4 บิต: ต่อ fa_struct 4 ตัว (เทียบรูปที่ 7.8)
2module adder4 (
3  input  [3:0] a, b,
4  input        cin,
5  output [3:0] s,
6  output       cout
7);
8  wire c1, c2, c3;                 // carry ระหว่างหลัก
9  fa_struct fa0 (.a(a[0]), .b(b[0]), .cin(cin), .s(s[0]), .cout(c1));
10  fa_struct fa1 (.a(a[1]), .b(b[1]), .cin(c1),  .s(s[1]), .cout(c2));
11  fa_struct fa2 (.a(a[2]), .b(b[2]), .cin(c2),  .s(s[2]), .cout(c3));
12  fa_struct fa3 (.a(a[3]), .b(b[3]), .cin(c3),  .s(s[3]), .cout(cout));
13endmodule

อย่างไรก็ตาม สำหรับวงจรบวกโดยทั่วไป เราเพียงเขียนแบบ dataflow บรรทัดเดียว assign {cout, s} = a + b + cin; (ไฟล์ adder4_df.v) แล้วปล่อยให้เครื่องมือสังเคราะห์เลือกโครงสร้างวงจรบวกที่เหมาะกับอุปกรณ์เป้าหมาย เช่น FPGA ส่วนใหญ่มีวงจร carry chain สำเร็จรูปที่เร็วกว่าการต่อ full-adder ทีละตัว ทั้งสองแบบให้ผลเหมือนกันทั้ง 512 กรณีของอินพุต

12.3.5 การหลีกเลี่ยงการเกิด latch

ข้อผิดพลาดที่พบบ่อยที่สุดในการเขียนวงจรคอมไบเนชันด้วย always @* คือการไม่กำหนดค่าให้เอาต์พุตในทุกกรณี พิจารณาโปรแกรมที่ 12.10

โปรแกรมที่ 12.10 ตัวอย่างโค้ดที่ทำให้เกิด latch โดยไม่ตั้งใจ (latch_bad.v)
1// ตัวอย่างที่ไม่ควรเขียน: ไม่กำหนดค่า y เมื่อ en = 0
2module latch_bad (
3  input      en, d,
4  output reg y
5);
6  always @* begin
7    if (en)
8      y = d;      // ไม่มี else -> y ต้อง "จำ" ค่าเดิม = latch
9  end
10endmodule

เมื่อ en = 0 โค้ดไม่ได้บอกว่า y มีค่าเท่าใด ตามความหมายของภาษา y จึงต้องคงค่าเดิมไว้ ซึ่งวงจรคอมไบเนชันทำไม่ได้ เครื่องมือสังเคราะห์จึงต้องสร้างวงจรแลทช์ (latch, บทที่ 8) ขึ้นมาเก็บค่า เมื่อสังเคราะห์โปรแกรมนี้ด้วย Yosys จะได้ผลเป็นเซลล์ $_DLATCH_P_ (D latch ที่โปร่งใสเมื่อ en = 1) เพียงหนึ่งตัว แทนที่จะเป็นเกต latch ที่เกิดโดยไม่ตั้งใจทำให้จังหวะเวลาของวงจรวิเคราะห์ได้ยาก และผลการจำลองอาจไม่ตรงกับวงจรจริง จึงควรหลีกเลี่ยงด้วยหลักต่อไปนี้

หลักการเขียนวงจรคอมไบเนชันด้วย always @*
  1. ใช้ always @* เสมอ ไม่ต้องเขียนรายการสัญญาณ (sensitivity list) เอง เพื่อไม่ให้ลืมสัญญาณใด
  2. กำหนดค่าตั้งต้นให้เอาต์พุตทุกตัวที่บรรทัดแรกของบล็อก (เช่นในโปรแกรมที่ 12.7) หรือ
  3. ให้ if ทุกตัวมี else และ case ทุกตัวมี default (เช่นในโปรแกรมที่ 12.6 และ 12.8)
  4. ใช้เครื่องหมาย = (blocking) ภายใน always @*

12.4 การอธิบายวงจรเชิงลำดับ

12.4.1 always @(posedge clk) และ D flip-flop

วงจรเชิงลำดับแบบ synchronous อธิบายด้วยบล็อก always ที่ทำงานเฉพาะที่ขอบของสัญญาณนาฬิกา คำว่า posedge หมายถึงขอบขาขึ้น (0 → 1) และ negedge หมายถึงขอบขาลง (1 → 0) สัญญาณ reg ที่ได้รับค่าในบล็อกนี้จะกลายเป็นฟลิปฟลอป โปรแกรมที่ 12.12 เป็น D flip-flop แบบ positive edge-triggered ที่มีขา reset แบบ asynchronous (active-LOW) ตามบทที่ 8

โปรแกรมที่ 12.12 D flip-flop พร้อม reset แบบ asynchronous (dff_ar.v)
1// D flip-flop ขอบขาขึ้น พร้อม reset แบบ asynchronous (active-LOW)
2module dff_ar (
3  input      clk, rst_n, d,
4  output reg q
5);
6  always @(posedge clk or negedge rst_n) begin
7    if (!rst_n)
8      q <= 1'b0;        // reset ทันทีไม่ต้องรอ clock
9    else
10      q <= d;           // รับค่า d ที่ขอบขาขึ้น
11  end
12endmodule

การใส่ negedge rst_n ไว้ในรายการเหตุการณ์ทำให้บล็อกทำงานทันทีที่ rst_n ลงเป็น 0 โดยไม่ต้องรอขอบสัญญาณนาฬิกา จึงเป็น reset แบบ asynchronous (เทียบกับขา CLR ในบทที่ 8–9) ถ้าต้องการ reset แบบ synchronous ให้เขียนเพียง always @(posedge clk) แล้วตรวจ if (!rst_n) ภายในเหมือนเดิม ชื่อ rst_n ที่ลงท้ายด้วย _n เป็นธรรมเนียมที่นิยมใช้บอกว่าสัญญาณเป็น active-LOW

12.4.2 Non-blocking (<=) กับ blocking (=)

ในโปรแกรมที่ 12.12 การกำหนดค่าใช้เครื่องหมาย <= ซึ่งเรียกว่า non-blocking assignment มีความหมายว่า “คำนวณค่าด้านขวาของทุกบรรทัดจากค่าก่อนขอบสัญญาณนาฬิกา แล้วจึงเปลี่ยนค่าด้านซ้ายทั้งหมดพร้อมกัน” ซึ่งตรงกับพฤติกรรมของฟลิปฟลอปจริงที่ทุกตัวสุ่มค่าอินพุตพร้อมกันที่ขอบสัญญาณนาฬิกา ส่วน = คือ blocking assignment ที่เปลี่ยนค่าทันทีก่อนทำบรรทัดถัดไป ความแตกต่างเห็นได้ชัดในโปรแกรมที่ 12.13

โปรแกรมที่ 12.13 เปรียบเทียบ non-blocking กับ blocking ในบล็อก always @(posedge clk) (pipe_nb.v)
1// เปรียบเทียบ non-blocking (<=) กับ blocking (=)
2module pipe_nb (input clk, d, output reg q1, q2);
3  always @(posedge clk) begin
4    q1 <= d;        // ทุกบรรทัดใช้ค่า "ก่อน" ขอบนาฬิกา
5    q2 <= q1;       // q2 ได้ค่า q1 เดิม -> FF 2 ตัวต่อกัน
6  end
7endmodule
8
9module pipe_b (input clk, d, output reg q1, q2);
10  always @(posedge clk) begin
11    q1 = d;         // q1 เปลี่ยนทันที
12    q2 = q1;        // q2 ได้ค่า d ใหม่ -> เหลือ FF ตัวเดียว
13  end
14endmodule

เมื่อป้อนลำดับ d = 0, 1, 1, 0, 1, 0 ให้ทั้งสองโมดูล ผลการจำลองในตารางที่ 12.3 แสดงว่าใน pipe_nb ค่า q2 ตามหลัง q1 อยู่หนึ่งจังหวะสัญญาณนาฬิกา (FF สองตัวต่อกันเป็นชิฟต์รีจิสเตอร์) แต่ใน pipe_b ค่า q2 เท่ากับ q1 ทุกจังหวะ เพราะบรรทัดที่สองอ่านค่า q1 ที่เพิ่งเปลี่ยนไปแล้ว วงจรที่ได้จึงต่างกันดังรูปที่ 12.4 ค่า x ในจังหวะแรกเกิดจาก q1 ยังไม่เคยได้รับค่าใดมาก่อน

12.4.3 รีจิสเตอร์และวงจรนับ

เมื่อสัญญาณใน always @(posedge clk) เป็นเวกเตอร์ เราจะได้ฟลิปฟลอปหลายตัวที่ใช้สัญญาณนาฬิกาเดียวกัน คือรีจิสเตอร์ เช่น รีจิสเตอร์ขนาด 4 บิตแบบโหลดขนาน (ไฟล์ reg4.v) เขียนได้เพียง if (load) q <= d; ภายใน always @(posedge clk) ซึ่งโหลดข้อมูลเมื่อ load = 1 และคงค่าเดิมเมื่อ load = 0 สังเกตว่าในวงจรเชิงลำดับ การไม่กำหนดค่าใน else ไม่ทำให้เกิด latch เพราะฟลิปฟลอปจำค่าเดิมได้อยู่แล้ว (เครื่องมือสังเคราะห์จะใช้ฟลิปฟลอปที่มีขา enable หรือ MUX ป้อนกลับ)

วงจรนับแบบ synchronous ในบทที่ 9 ต้องออกแบบผ่านตารางสถานะ ตาราง transition และแผนผังคาร์โนห์ แต่ในระดับ RTL เราเพียงเขียนว่า “ค่าถัดไปคือค่าปัจจุบันบวกหนึ่ง” ดังโปรแกรมที่ 12.14 ซึ่งเป็นวงจรนับขึ้น/ลง (up/down counter) ขนาด 4 บิตที่มีขา enable เมื่อ q = 15 แล้วบวก 1 ผลลัพธ์ขนาด 4 บิตจะวนกลับเป็น 0 เอง และเมื่อ q = 0 แล้วลบ 1 จะได้ 15 จึงเป็นวงจรนับ MOD-16 โดยไม่ต้องเขียนเงื่อนไขพิเศษ

โปรแกรมที่ 12.14 วงจรนับขึ้น/ลงขนาด 4 บิต ที่มีขา enable (counter4.v)
1// วงจรนับขึ้น/ลงขนาด 4 บิต แบบ synchronous มีขา enable
2module counter4 (
3  input            clk, rst_n,
4  input            en,      // 1 = นับ, 0 = หยุด
5  input            up,      // 1 = นับขึ้น, 0 = นับลง
6  output reg [3:0] q
7);
8  always @(posedge clk or negedge rst_n) begin
9    if (!rst_n)
10      q <= 4'd0;
11    else if (en) begin
12      if (up) q <= q + 4'd1;   // 15 -> 0
13      else    q <= q - 4'd1;   //  0 -> 15
14    end
15  end
16endmodule

12.4.4 ชิฟต์รีจิสเตอร์

ชิฟต์รีจิสเตอร์แบบอนุกรมเข้า–ขนานออก (SIPO) ในหัวข้อ 9.5 เขียนได้ด้วยการต่อบิตเพียงบรรทัดเดียว q <= {din, q[3:1]}; หมายถึงให้ din เข้าไปที่บิตบนสุด และบิตเดิม q[3:1] เลื่อนลงมาหนึ่งตำแหน่ง ส่วน q[0] เดิมหลุดออกไป ดังโปรแกรมที่ 12.15 และรูปที่ 12.5 เนื่องจากใช้ <= ทุกบิตจึงเลื่อนพร้อมกันอย่างถูกต้อง

โปรแกรมที่ 12.15 ชิฟต์รีจิสเตอร์ขนาด 4 บิต แบบอนุกรมเข้า–ขนานออก (shift4.v)
1// ชิฟต์รีจิสเตอร์ขนาด 4 บิต อนุกรมเข้า-ขนานออก (SIPO) เลื่อนขวา
2module shift4 (

4  input            din,           // ข้อมูลอนุกรมเข้า
5  output reg [3:0] q              // q[3] = FF0 ... q[0] = FF3
6);
7  always @(posedge clk or negedge rst_n) begin
8    if (!rst_n)
9      q <= 4'b0000;
10    else
11      q <= {din, q[3:1]};          // เลื่อนไปทางขวา 1 ตำแหน่ง
12  end
13endmodule

12.4.5 การเขียน state machine

state machine (บทที่ 10) ประกอบด้วยรีจิสเตอร์สถานะและวงจรคอมไบเนชันที่คำนวณสถานะถัดไปและเอาต์พุต วิธีเขียนที่นิยมและอ่านง่ายคือแบบ always สองบล็อก ดังรูปที่ 12.6 บล็อกแรกเป็น always @(posedge clk) ที่ทำหน้าที่รีจิสเตอร์สถานะเพียงอย่างเดียว บล็อกที่สองเป็น always @* ที่เขียนผังสถานะเป็นคำสั่ง case หนึ่งกรณีต่อหนึ่งสถานะ และตั้งชื่อสถานะด้วย localparam เพื่อให้อ่านง่ายแทนการใช้รหัสไบนารีโดยตรง

ตัวอย่างคือวงจรตรวจจับลำดับ “101” แบบ Moore ที่ให้เอาต์พุต z = 1 เป็นเวลาหนึ่งจังหวะหลังจากรับบิต 1, 0, 1 ติดกันครบ โดยยอมให้ลำดับซ้อนกันได้ (overlapping) เช่น อินพุต 10101 จะตรวจพบสองครั้ง ผังสถานะแสดงในรูปที่ 12.7 ซึ่งมี 4 สถานะ S0 (ยังไม่พบส่วนใดของลำดับ), S1 (พบ “1”), S2 (พบ “10”) และ S3 (พบ “101”) แปลงเป็นโค้ดได้โดยตรงดังโปรแกรมที่ 12.16

โปรแกรมที่ 12.16 วงจรตรวจจับลำดับ 101 แบบ Moore (always สองบล็อก) (det101.v)
1// วงจรตรวจจับลำดับ "101" แบบ Moore (ยอมให้ลำดับซ้อนกัน)
2module det101 (
3  input      clk, rst_n, x,
4  output reg z
5);
6  localparam S0 = 2'd0,   // ยังไม่พบส่วนใดของลำดับ
7             S1 = 2'd1,   // พบ "1"
8             S2 = 2'd2,   // พบ "10"
9             S3 = 2'd3;   // พบ "101" -> z = 1
10  reg [1:0] state, next;
11
12  // (1) รีจิสเตอร์สถานะ
13  always @(posedge clk or negedge rst_n)
14    if (!rst_n) state <= S0;
15    else        state <= next;
16
17  // (2) วงจรคอมไบเนชัน: สถานะถัดไปและเอาต์พุต
18  always @* begin
19    next = state;  z = 1'b0;          // ค่าตั้งต้น
20    case (state)
21      S0: next = x ? S1 : S0;
22      S1: next = x ? S1 : S2;
23      S2: next = x ? S3 : S0;
24      S3: begin z = 1'b1; next = x ? S1 : S2; end
25    endcase
26  end
27endmodule

ข้อสังเกตเกี่ยวกับโปรแกรมที่ 12.16

  • บรรทัดที่ 19 กำหนดค่าตั้งต้น next = state; z = 1'b0; ก่อน case จึงไม่เกิด latch แม้บางกรณีจะไม่ได้กำหนด z
  • เอาต์พุต z ขึ้นกับสถานะเท่านั้น (เขียนไว้เฉพาะใน S3) ตามนิยามของ Moore machine ถ้าเป็น Mealy machine z จะขึ้นกับทั้งสถานะและ x เช่น S2: z = x;
  • การเปลี่ยนสถานะทั้งหมดเกิดในบล็อกที่ 1 ด้วย <= ส่วนบล็อกที่ 2 คำนวณด้วย = ตามกฎในหัวข้อ 12.4.2

การดูผลการจำลองด้วยตาเหมาะกับวงจรเล็กเท่านั้น testbench ที่ดีควรตรวจสอบตัวเอง (self-checking) คือคำนวณค่าที่คาดหวังแล้วเปรียบเทียบกับเอาต์พุตของ DUT โดยอัตโนมัติ และรายงานผลสรุปว่าผ่าน (PASS) หรือไม่ สำหรับวงจรคอมไบเนชันที่มีอินพุตไม่มาก ควรทดสอบครบทุกกรณี (exhaustive test) ด้วยลูป for ดังโปรแกรมที่ 12.17 ซึ่งทดสอบ full-adder ครบ 8 กรณีของตารางที่ 7.2

12.6 การสังเคราะห์วงจร

12.6.1 ขั้นตอนของการสังเคราะห์

การสังเคราะห์วงจร (logic synthesis) คือการแปลงโค้ดระดับ RTL ให้เป็น netlist ของเซลล์พื้นฐานที่มีอยู่จริงในอุปกรณ์เป้าหมาย ภายในเครื่องมือสังเคราะห์แบ่งได้เป็นสามขั้นตอนใหญ่ดังรูปที่ 12.11

  1. แปลความหมาย (elaboration) อ่านโค้ด ต่อโมดูลย่อยเข้าด้วยกัน แล้วแปลงโครงสร้างภาษาเป็นวงจรระดับ RTL เช่น + เป็นวงจรบวก ?: และ case เป็น MUX บล็อก always @(posedge clk) เป็นฟลิปฟลอป
  2. ปรับให้เหมาะสม (optimization) ลดรูปลอจิกด้วยหลักการเดียวกับพีชคณิตบูลีนและแผนผังคาร์โนห์ในบทที่ 4–5 แต่ใช้อัลกอริทึมที่จัดการตัวแปรจำนวนมากได้ ตัดวงจรที่ไม่มีผลต่อเอาต์พุตออก และรวมวงจรที่ซ้ำกัน
  3. แมปลงเทคโนโลยี (technology mapping) แปลงลอจิกเป็นเซลล์ที่อุปกรณ์มีจริง สำหรับชิป ASIC คือเกตในไลบรารีของโรงงานผลิต สำหรับ FPGA คือ LUT และฟลิปฟลอปในบล็อกลอจิก (หัวข้อ 11.2.3)

12.6.2 ผลการสังเคราะห์วงจรคอมไบเนชัน

ในหัวข้อนี้ใช้โปรแกรม Yosys ซึ่งเป็นเครื่องมือสังเคราะห์แบบโอเพนซอร์ส สังเคราะห์ full-adder แบบพฤติกรรมในโปรแกรมที่ 12.5 โดยสั่งให้แมปลงเกต AND, OR และ XOR ด้วยคำสั่งต่อไปนี้ ผลที่ได้คือ netlist ที่เขียนกลับเป็น Verilog ระดับเกต

คำสั่ง (terminal)
$ yosys -p "read_verilog fa_behav.v; synth -top fa_behav;
           abc -g AND,OR,XOR; opt_clean; write_verilog fa_gates.v"
netlist ที่ได้ (ตัดเฉพาะส่วนของลอจิก)
assign _0_ = a & b;
assign _1_ = a ^ b;
assign _2_ = cin & _1_;
assign cout = _0_ | _2_;
assign s = cin ^ _1_;

เมื่อวาด netlist นี้เป็นผังวงจรจะได้รูปที่ 12.12 ซึ่งมี XOR 2 ตัว AND 2 ตัว และ OR 1 ตัว เหมือนวงจร full-adder ในรูปที่ 7.5 และรูปที่ 12.2 ทุกประการ สายภายใน _0_, _1_ และ _2_ เป็นชื่อที่เครื่องมือตั้งขึ้นเอง ซึ่งตรงกับ g, p และ t ในโปรแกรมที่ 12.2 ตามลำดับ แสดงให้เห็นว่าเราไม่จำเป็นต้องเขียนวงจรระดับเกตเอง

ถ้าอุปกรณ์เป้าหมายเป็น FPGA ที่ใช้ LUT ขนาด 4 อินพุต (สั่ง synth -lut 4) เครื่องมือจะไม่ใช้เกตเลย แต่บรรจุฟังก์ชันของ s และ cout ลงใน LUT คนละตัว แต่ละ LUT เป็นหน่วยความจำขนาดเล็กที่เก็บตารางค่าความจริงไว้ โดยใช้อินพุตเป็นตำแหน่งที่อยู่ ค่าเริ่มต้น (INIT) ที่ได้คือ 8'h96 สำหรับ s และ 8'he8 สำหรับ cout ซึ่งเมื่อเขียนเป็นเลขฐานสองทีละบิตก็คือคอลัมน์เอาต์พุตของตารางที่ 7.2 นั่นเอง ดังรูปที่ 12.13

12.6.3 ผลการสังเคราะห์วงจรเชิงลำดับ

วงจรนับขึ้นขนาด 4 บิตที่มีขา enable (ไฟล์ upcnt4.v ซึ่งเหมือนโปรแกรมที่ 12.14 แต่ไม่มีขา up) สังเคราะห์ได้ฟลิปฟลอปชนิดที่มีขา enable จำนวน 4 ตัว และเกตอีก 6 ตัว ดังรูปที่ 12.14 สมการที่ได้คือ D0 = q0, D1 = q1 ⊕ q0, D2 = q2 ⊕ q1q0 และ D3 = q3 ⊕ q2q1q0 คือบิตใดจะกลับค่า (toggle) เมื่อบิตที่ต่ำกว่าทั้งหมดเป็น 1 ซึ่งเป็นหลักการเดียวกับวงจรนับแบบ synchronous ที่ใช้ J-K flip-flop และเกต AND ในบทที่ 9 ทั้งที่ในโค้ดเราเขียนเพียง q <= q + 4'd1;

สำหรับวงจรตรวจจับลำดับ 101 ถ้าสั่งให้คงการเข้ารหัสสถานะแบบไบนารีตามที่เขียนไว้ (synth -nofsm) จะได้ฟลิปฟลอป 2 ตัวและเกตเพียงไม่กี่ตัว ดังรูปที่ 12.15 ซึ่งให้สมการ D0 = x, D1 = s0x · (s0 + x s1) และ z = s1s0 (เมื่อ s1s0 คือรหัสสถานะ S0 = 00, S1 = 01, S2 = 10, S3 = 11) ผู้เรียนสามารถตรวจสอบได้ด้วยวิธีวิเคราะห์วงจรเชิงลำดับในบทที่ 10 ว่าได้ผังสถานะเดียวกับรูปที่ 12.7

หมายเหตุ ถ้าสังเคราะห์ด้วยค่าปกติ Yosys จะตรวจพบว่า state เป็น state machine และเปลี่ยนการเข้ารหัสเป็นแบบ one-hot (ฟลิปฟลอปหนึ่งตัวต่อหนึ่งสถานะ) โดยอัตโนมัติ ได้ฟลิปฟลอป 4 ตัว เพราะใน FPGA ซึ่งมีฟลิปฟลอปจำนวนมาก การเข้ารหัสแบบนี้มักทำให้วงจรคอมไบเนชันง่ายและเร็วกว่า การที่เครื่องมือเปลี่ยนรายละเอียดภายในได้โดยที่พฤติกรรมภายนอกยังเหมือนเดิมเป็นข้อดีของการออกแบบในระดับ RTL netlist ทุกแบบในหัวข้อนี้ได้รับการจำลองการทำงานเทียบกับโค้ด RTL แล้วให้ผลตรงกันทั้ง 2008 กรณี

ตารางที่ 12.5 สรุปขนาดของวงจรในบทนี้เมื่อสังเคราะห์ด้วย Yosys ทั้งแบบเกตพื้นฐาน และแบบ LUT 4 อินพุตสำหรับ FPGA จะเห็นว่าขนาดของโค้ดไม่ได้บอกขนาดของวงจร เช่น ตัวถอดรหัส 7 segment มีโค้ดเพียงไม่กี่บรรทัดแต่ใช้เกตมากที่สุด ในขณะที่ชิฟต์รีจิสเตอร์ใช้ฟลิปฟลอปอย่างเดียวโดยไม่มีเกตเลย

12.6.5 จากโค้ดสู่ FPGA

เมื่อนำความรู้ในบทนี้ไปรวมกับโฟลว์การออกแบบในบทที่ 11 ขั้นตอนการสร้างวงจรบน FPGA จริงคือ เขียนโมดูลระดับ RTL ด้วย synthesizable subset (design entry) → ทดสอบด้วย testbench แบบตรวจสอบตัวเองจนผ่าน (functional simulation) → สังเคราะห์เป็น LUT และฟลิปฟลอปแล้วตรวจรายงานคำเตือน โดยเฉพาะ latch ที่เกิดโดยไม่ตั้งใจ (synthesis) → กำหนดขาของชิปให้พอร์ตแต่ละตัว เช่น clk ต่อกับออสซิลเลเตอร์บนบอร์ด แล้วจัดวางและเดินสาย (implementation) → ตรวจว่าเวลาหน่วงจริงสั้นกว่าคาบของสัญญาณนาฬิกา (timing analysis) → ดาวน์โหลด bitstream ลงอุปกรณ์ ซอฟต์แวร์ของผู้ผลิต เช่น AMD Vivado และ Intel Quartus Prime รวมทุกขั้นตอนไว้ในโปรแกรมเดียว ส่วนเครื่องมือโอเพนซอร์ส เช่น Icarus Verilog, Yosys และ nextpnr เหมาะสำหรับการเรียนรู้หลักการ

  1. จงอธิบายความแตกต่างระหว่าง (ก) การจำลองการทำงานกับการสังเคราะห์วงจร (ข) สัญญาณชนิด wire กับ reg และ (ค) = กับ <=
  2. กำหนดให้ a = 8'hA5 และ b = 8'h3C จงหาค่าของ a & b, a ^ b, ^a, |b, {a[3:0], b[7:4]}, a >> 3 และ (a < b) ? a : b เป็นเลขฐานสอง
  3. จงเขียนโมดูล comparator ขนาด 4 บิต (หัวข้อ 7.3) ที่มีเอาต์พุต eq, gt และ lt ด้วยคำสั่ง assign แล้วเขียน testbench ที่ทดสอบครบทั้ง 256 กรณี
  4. จงเขียนโมดูล DEMUX 1-to-4 (หัวข้อ 7.8) ด้วย always @* และ case โดยไม่ให้เกิด latch

  5. โค้ดต่อไปนี้จะสังเคราะห์ได้วงจรอะไร

    module ex_mux (input a, b, c, d, input [1:0] s, output y);
  assign y = s[1] ? (s[0] ? d : c) : (s[0] ? b : a);
endmodule

  6. โค้ดต่อไปนี้มีข้อผิดพลาดอะไร วงจรที่สังเคราะห์ได้จะมีอะไรเกินมา และควรแก้ไขอย่างไร

    module ex_latch (input [1:0] s, input a, b, c, output reg y);
  always @* begin
    case (s)
      2'b00: y = a;
      2'b01: y = b;
      2'b10: y = c;
    endcase
  end
endmodule

  7. โค้ดต่อไปนี้จะสังเคราะห์ได้วงจรอะไร จงวาดวงจรและอธิบายผลเมื่อเปลี่ยน <= ทั้งสองบรรทัดเป็น =

    module ex_swap (input clk, output reg a, b);
  always @(posedge clk) begin
    a <= b;
    b <= a;
  end
endmodule

  8. จงวาดวงจรที่ได้จากโค้ดต่อไปนี้ และหาลำดับค่าของ q หลังจาก reset เป็นเวลา 6 จังหวะ วงจรนี้คือวงจรนับชนิดใด

    module ex_cnt (input clk, rst_n, output reg [2:0] q);
  always @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 3'd0;
    else        q <= {q[1:0], ~q[2]};
endmodule
  9. จงเขียนโมดูลวงจรตรวจจับลำดับ “110” แบบ Moore ที่ยอมให้ลำดับซ้อนกันได้ ด้วยรูปแบบ always สองบล็อก พร้อมทั้งเขียน testbench ป้อนลำดับบิตที่มีคำตอบทราบล่วงหน้า
  10. จงเขียนโมดูลวงจรนับทศวรรษ (BCD counter, MOD-10) แบบ synchronous ที่มีขา enable และเอาต์พุต tc (terminal count) เป็น 1 เมื่อ q = 9 และ en = 1 แล้วนำสองตัวมาต่อกันเป็นวงจรนับ 00–99

สรุปท้ายบท

  • HDL อธิบายโครงสร้างและพฤติกรรมของวงจรที่ทำงานพร้อมกัน ภาษาหลักคือ Verilog และ VHDL โค้ดชุดเดียวกันใช้ได้ทั้งการจำลองการทำงานและการสังเคราะห์ แต่การสังเคราะห์รองรับเฉพาะ synthesizable subset
  • โมดูล Verilog มีพอร์ต input/output สัญญาณชนิด wire (ขับด้วย assign หรือเกต) และ reg (กำหนดค่าใน always) ค่าคงที่เขียนในรูป 4'b1010, 8'hFF และมีตัวดำเนินการแบบ bitwise, reduction, arithmetic, relational, ?: และ { }
  • วงจรคอมไบเนชันเขียนได้แบบโครงสร้าง (gate primitive) แบบ dataflow (assign) หรือแบบพฤติกรรม (always @* กับ =) ซึ่งต้องกำหนดค่าเอาต์พุตครบทุกกรณีเพื่อไม่ให้เกิด latch
  • วงจรเชิงลำดับเขียนด้วย always @(posedge clk) และ <= ได้แก่ ฟลิปฟลอป รีจิสเตอร์ วงจรนับ และชิฟต์รีจิสเตอร์ ส่วน state machine นิยมเขียนแบบ always สองบล็อก โดยตั้งชื่อสถานะด้วย localparam
  • testbench เป็นโมดูลไม่มีพอร์ตที่สร้างอินพุต ป้อนให้ DUT และตรวจผลกับค่าที่คาดหวังโดยอัตโนมัติ ควรทดสอบครบทุกกรณีเมื่อทำได้ และใช้ไฟล์ VCD ดูผังเวลา
  • การสังเคราะห์แปลงโค้ด RTL เป็น netlist ผ่านการแปลความหมาย การปรับให้เหมาะสม และการแมปลงเกตหรือ LUT/ฟลิปฟลอป ผลที่ได้ เช่น full-adder และวงจรนับ ตรงกับวงจรที่ออกแบบด้วยมือในบทก่อน ๆ ส่วน #, initial และ $display ใช้ได้เฉพาะในการจำลอง
